# Requisitos funcionais

Os requisitos abaixo foram obtidos somente a partir das necessidades explicitamente mencionadas no documento.

| ID | Requisito funcional | Stakeholder/Origem | Prioridade sugerida | Observações |
|---|---|---|---|---|
| RF-001 | O sistema deve permitir ao participante visualizar os eventos disponíveis. | Participantes | Alta | Requisito explicitamente solicitado. |
| RF-002 | O sistema deve permitir ao participante realizar inscrição em eventos. | Participantes / contexto | Alta | Função central do sistema. |
| RF-003 | O sistema deve permitir ao participante acompanhar suas inscrições. | Participantes / stakeholders | Alta | Explicitamente descrito no interesse do stakeholder. |
| RF-004 | O sistema deve disponibilizar um comprovante da inscrição realizada. | Participantes | Média | Forma de disponibilização ainda não definida. |
| RF-005 | O sistema deve permitir ao participante solicitar o cancelamento de uma inscrição quando o evento permitir cancelamento. | Participantes / Organizadores | Alta | Prazo e condições ainda precisam ser definidos. |
| RF-006 | O sistema deve permitir ao participante emitir seu certificado após o evento. | Participantes | Alta | Critério para liberação do certificado ainda não definido. |
| RF-007 | O sistema deve permitir que um participante realize inscrição em mais de um workshop no mesmo dia. | Participantes | Média | Não está definido o tratamento de conflitos de horário. |
| RF-008 | O sistema deve permitir ao organizador criar eventos. | Organizadores | Alta | Explicitamente indicado nos interesses do stakeholder. |
| RF-009 | O sistema deve controlar automaticamente a quantidade de vagas disponíveis em cada evento ou atividade. | Organizadores | Alta | Requisito central de controle. |
| RF-010 | O sistema deve permitir acompanhar a quantidade de inscritos em tempo real. | Organizadores | Alta | Explicitamente solicitado. |
| RF-011 | O sistema deve permitir ao organizador acompanhar as inscrições realizadas. | Organizadores | Alta | Explicitamente descrito nos interesses do stakeholder. |
| RF-012 | O sistema deve permitir ao organizador gerenciar os participantes dos eventos. | Organizadores | Alta | O significado de “gerenciar” precisa posteriormente ser detalhado. |
| RF-013 | O sistema deve disponibilizar uma lista de espera quando um evento atingir sua capacidade máxima. | Organizadores | Média | Funcionamento da lista de espera ainda não definido. |
| RF-014 | O sistema deve permitir configurar eventos gratuitos e eventos pagos. | Equipe Financeira | Alta | Explicitamente informado. |
| RF-015 | O sistema deve permitir a confirmação de pagamentos das inscrições. | Equipe Financeira | Alta | Há inscrições que somente serão liberadas após confirmação. |
| RF-016 | O sistema deve liberar determinadas inscrições somente após a confirmação do pagamento. | Equipe Financeira | Alta | Critérios para determinar quais inscrições dependem do pagamento precisam ser definidos. |
| RF-017 | O sistema deve permitir tratar reembolsos quando aplicáveis. | Equipe Financeira | Média | Condições de elegibilidade precisam ser definidas. |
| RF-018 | O sistema deve permitir ao palestrante consultar os participantes inscritos em suas atividades. | Palestrantes | Média | Dados que poderão ser visualizados ainda precisam ser definidos. |
| RF-019 | O sistema deve permitir a realização simultânea de workshops programados para o mesmo horário. | Organizadores | Média | Trata-se principalmente de uma regra de programação do evento. |

## Observação

Os requisitos RF-005, RF-006, RF-013, RF-016, RF-017 e RF-018 representam funcionalidades claramente desejadas, mas possuem regras internas ainda incompletas.

Isso significa que a existência da funcionalidade pode ser especificada, mas seu comportamento completo somente poderá ser definido após novas conversas com os stakeholders.
